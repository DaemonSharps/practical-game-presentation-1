# AGENTS.md — обязательная инструкция для проекта

Этот файл предназначен для учителя и нейросетей, которые создают или изменяют интерактивные презентации. Проект рассчитан на человека, который может не знать JavaScript. Поэтому любое изменение должно быть маленьким, понятным и проверяемым.

## 1. Что это за проект

Это статический сайт с каталогом и несколькими презентациями на reveal.js. Каждая презентация живёт в отдельной папке внутри `presentations/`. Общие стили и игровые функции находятся в `src/`.

Основные команды:

```bash
npm install       # выполнить один раз после скачивания проекта
npm run dev       # открыть локальный режим разработки
npm run build     # обязательная проверка перед публикацией
npm run preview   # посмотреть собранную версию
```

## 2. Жёсткие запреты

Никогда не делайте следующие вещи:

1. Не удаляйте `package.json`, `vite.config.js`, `vercel.json`, `.gitignore`, `src/presentation.js` и `src/shared.css`, если не понимаете, зачем они нужны.
2. Не вставляйте токены, пароли, ключи API, ссылки с секретными параметрами и персональные данные учеников в код, HTML, историю Git или сообщения коммитов.
3. Не переименовывайте папки `src` и `presentations`.
4. Не используйте абсолютные пути с `C:\`, `/Users/...` или `/home/...`; сайт должен собираться на любом компьютере и в Vercel.
5. Не подключайте библиотеки через случайные CDN-ссылки без согласования. Новую зависимость сначала добавляйте в `package.json`, затем запускайте `npm install` и фиксируйте lock-файл.
6. Не изменяйте версию `reveal.js` без проверки всей презентации: плагины и API могут отличаться между версиями.
7. Не меняйте `vite.config.js`, если задача — только добавить слайды. Для новой презентации достаточно новой папки.
8. Не помещайте в презентацию настоящие фамилии, оценки, телефоны, адреса или другие данные детей.
9. Не добавляйте игры, которые требуют регистрации ученика, передачи данных третьим лицам, скачивания неизвестных файлов или доступа к микрофону/камере без отдельного согласия.
10. Не используйте таймеры, звуки, мигание или внезапные анимации как обязательную часть задания: у ученика должна оставаться доступная альтернатива.
11. Не удаляйте `aria-live`, подписи кнопок и текстовую обратную связь ради «красоты».
12. Не коммитьте папки `node_modules`, `dist`, `.vercel` и файлы `.env`.
13. Не переименовывайте существующие маршруты без обновления ссылок в каталоге.
14. Не выполняйте команды удаления или очистки репозитория, если точный список файлов заранее не проверен.

## 3. Правильная структура новой презентации

```text
presentations/
└── slug-prezentacii/
    ├── index.html   # слайды reveal.js
    └── main.js      # интерактив этой презентации
```

Название `slug` должно состоять из латинских букв, цифр и дефисов. Не используйте пробелы, кириллицу и символы `?`, `#`, `%`.

Начинайте новую презентацию копированием `presentations/demo`. Не создавайте отдельную npm-конфигурацию внутри презентации.

В `index.html` сохраняйте:

```html
<div class="reveal">
  <div class="slides">
    <!-- section = один слайд -->
  </div>
</div>
<script type="module" src="./main.js"></script>
```

В `main.js` импортируйте общую функцию запуска:

```js
import { startPresentation } from '../../src/presentation.js';

startPresentation();
```

Если презентация находится глубже одного уровня, скорректируйте количество `../`, но не меняйте имя файла `src/presentation.js`.

## 4. Правила контента для 5–10 классов

- На одном слайде должна быть одна учебная задача.
- Инструкция должна отвечать на три вопроса: что сделать, сколько времени есть, что нужно предъявить.
- Не прячьте правильный ответ только в цвете. Используйте текстовую обратную связь.
- После мини-игры добавляйте объяснение способа действия, а не только «верно/неверно».
- Сложные задания делите на короткие шаги.
- Не делайте соревнование обязательным. Формулировки «победил/проиграл» заменяйте на «проверяем способ» или «сравниваем стратегии».
- Для 5–6 классов используйте короткие фразы и один новый термин за раз.
- Для 7–8 классов добавляйте выбор стратегии и объяснение ошибки.
- Для 9–10 классов можно добавлять ограничение времени, несколько условий и рефлексию.
- Все факты, правила русского языка, литературные сведения и ответы учитель обязан проверить по своему учебнику, ФИПИ или другому заранее выбранному авторитетному источнику. Нейросеть не является источником истины.

## 5. Безопасный интерактив

Разрешённые базовые механики:

- выбор ответа с блокировкой повторного клика;
- текстовая обратная связь;
- локальный таймер без отправки данных;
- раскрытие подсказки;
- подсчёт результата только в текущем браузере;
- переходы между слайдами reveal.js.

Перед добавлением механики проверьте:

1. Работает ли она с клавиатуры.
2. Понятно ли, что произошло после клика.
3. Есть ли способ продолжить урок без механики.
4. Не сохраняются ли данные после закрытия страницы.
5. Не зависит ли ответ только от цвета, звука или скорости реакции.

Не добавляйте `eval`, вставку произвольного HTML из пользовательского ввода, внешние формы и запросы к API без отдельной технической задачи.

## 6. Работа с нейросетью

Нейросети можно поручать:

- создать структуру слайдов;
- предложить варианты формулировок;
- написать локальную механику на основе существующих функций;
- адаптировать объяснение под класс;
- найти потенциальные ошибки для ручной проверки.

Нейросети нельзя без проверки доверять:

- правильность ответов;
- цитаты и авторство;
- даты, статистику и ссылки;
- соответствие ФГОС, демоверсии и актуальным критериям экзамена;
- безопасность стороннего кода.

Всегда просите нейросеть менять только конкретную папку презентации и не трогать конфигурацию проекта. После генерации просмотрите diff и выполните `npm run build`.

- [ ] Открывается корневой каталог.
- [ ] Открывается новая презентация по прямой ссылке.
- [ ] Все кнопки имеют понятный текст.
- [ ] Нельзя случайно нажать ответ дважды и получить противоречивый результат.
- [ ] Есть текстовая обратная связь.
- [ ] Презентация читается на узком экране.
- [ ] В коде нет секретов и персональных данных.
- [ ] В каталоге есть ссылка на новую презентацию.
- [ ] Изменены только нужные файлы.

## 8. Коммиты и Vercel

Коммит должен описывать одно изменение, например:

```text
Добавить игру на повторение частей речи
Исправить таймер в презентации по синтаксису
Обновить карточку презентации в каталоге
```

Для Vercel не нужны переменные окружения: это статический проект. Если Vercel просит Root Directory, оставьте корень репозитория. Build Command: `npm run build`. Output Directory: `dist`. Install Command: `npm install`.

Не добавляйте токены Vercel в репозиторий. Если проект подключён к GitHub через Vercel, изменения в основной ветке могут автоматически запускать production-деплой, поэтому перед push обязательно выполняйте локальную сборку.

## 9. Что делать при ошибке

1. Скопируйте полный текст ошибки.
2. Укажите файл и действие, после которого ошибка появилась.
3. Не удаляйте lock-файл и не переустанавливайте всё подряд.
4. Сначала выполните `npm run build` и проверьте первую ошибку сверху.
5. Если ошибка связана с новой презентацией, временно уберите только её папку из `presentations/` и проверьте, собирается ли остальной проект.
6. При сомнении остановитесь и попросите технически знакомого человека проверить diff.
